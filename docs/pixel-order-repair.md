# 舊生產 PNG 像素修補與獨立人工重印

本次依店主改變的需求，在 #109 增加「以原始生產圖進行修改」。不再要求從空白重排，也不把已合成的 PNG 說成原始可編輯圖層。沿用前台 Fabric 工具新增照片、貼紙、文字、可移動縮放的局部遮蓋與擦除矩形。

## 缺歷史刀模時的安全方案

- 原圖使用訂單保存的 print_path，需可解碼 PNG、720 DPI，最多 1800 萬像素。V1 私有歸檔以完整原檔與 SHA256 保存。
- 畫布底圖不可選取，僅顯示比例縮小；輸出只輸出透明新增圖層與擦除遮罩，V1 不經瀏覽器再次壓縮、重採樣或轉色。
- 伺服器使用 V1 原生像素座標合成；沒有修改的每個 RGBA 值必須相同。輸出尺寸保持完全一致，DPI 為 720，保留原 ICC／gamma；Safari 新增圖層有 ICC 時只轉換新增像素至原色域。
- 原 alpha=0 的區域完全禁止新增內容，半透明邊緣也不增加 alpha。這是保守的修補邊界，不是推算刀模。擦除只減少指定區域 alpha。粉紅色矩形表示待擦除區，保存後比較實際生產圖。
- 不讀現行型號模板來補定位。只有歷史 print_job 的 artwork SHA 與 V1 一致、W/H 與原圖 720 DPI 尺寸一致，且歷史定位無衝突時，才能使用該任務 W/H、X/Y、角度、通道。缺證據可保存草稿，禁止確認或送印。

## 版本與列印安全

V1 原檔不變；明確保存產生 V2，後續修改追加版本。以版本 CAS 防止併發覆蓋。素材與生產圖均經管理員驗證端點提供，不使用公開素材網址或客人的 IndexedDB。已存在其他編輯模式的版本不會被轉換覆蓋。

先保存，再開啟 V1／V2 比較（可點開原尺寸 PNG）。圖片載入失敗不可確認。人工輸入重印原因與成本，確認精確版本 SHA 後建立 PREPARED 獨立任務；另按「傳送至銳印」才使用既有 receiveTask 安全流程。每個版本固定一個 idempotency identity，重複確認／傳送不建立第二筆；UNKNOWN 需列印中心查核。先前未結束或不明任務會阻擋新確認。

重印任務沿用 manual_independent，callback 不改訂單。原因、成本（整數分）、操作者、版本 SHA、V1/V2 檔案 SHA 與來源任務寫入新任務 audit event；不寫原訂單／原任務／銷售帳／庫存。V2 再次需要重印時應建立並確認另一個設計版本，不提供任意重放同一授權。

## Migration 與部署

新增 `20261117111435_pixel_order_reprint.sql`，增加 service_role 可呼叫的 `approve_pixel_reprint` 及只保護新像素修補任務的定位／檔案不可變更 trigger，無資料回填。確認後，既有列印中心的「套用參數」也不能取代已確認的歷史定位；狀態與查核照常更新。複用 #108 版本表及既有列印表。必須先於隔離 PostgreSQL 通過 migration、權限與多連線競爭測試，再由店主核准正式 migration。

`ORDER_PIXEL_REPRINT_ENABLED` 預設關閉；開關只控制確認／送印，保存與比較可用。正式部署須先套用新增 RPC，再經核對啟用；缺 RPC 或開關關閉會拒絕確認，絕不默默改用舊送印。回退時關閉開關並保留版本資料，勿刪除有 audit 的任務。

需要主機足夠記憶體處理原生 PNG；超出像素／素材上限會拒絕。第一版提供矩形擦除及覆蓋修補，不是 AI 自動還原被合成遮住的內容，也不能把原圖中的某張貼紙單獨抽出。底圖為最終像素，原圖透明區不擴張限制可能需要重新設計才能處理超出舊輪廓的需求。

隔離驗收入口：test_pixel_orders.py、.github/tests/test_pixel_order_browser.py、.github/tests/test_pixel_order_postgres.py。CI 接入既有 Smoke／Commerce／Print Center／PostgreSQL／WebKit／Chromium，全部假 vendor，禁止對正式系統執行測試或 migration。
